Case 1: Electric Vehicle Manufacturer Transformation

Architect Level Complex

📌 Scenario

A traditional auto manufacturer is pivoting to electric vehicles. They have:

  • Legacy ERP for internal combustion engine production
  • New battery tech R&D that needs agile development
  • Direct-to-consumer sales model (no dealers)
  • Software-defined vehicle features (OTA updates)
  • Global regulatory compliance requirements
  • Existing dealer network pushing back

Your Task

Using the 9-step defense pattern, provide a complete architecture recommendation:

  1. Context — Describe the situation
  2. Objective — Define the business outcome
  3. Constraints — List key constraints
  4. Recommendation — Your architectural approach
  5. Architecture rationale — Why it fits
  6. Trade-off — What you're sacrificing
  7. Risk — Biggest risk and mitigation
  8. Roadmap — Sequence of work
  9. Validation — How to measure success
📖 View Model Answer

1. Context: Traditional manufacturer transitioning to EV with legacy systems and new business models.

2. Objective: Launch EV product in 24 months with direct-to-consumer sales and OTA capabilities.

3. Constraints: Existing dealer agreements, regulatory approvals, R&D timeline, budget constraints.

4. Recommendation: Two-speed IT - maintain legacy for core manufacturing, build new cloud-native platform for EV and D2C.

5. Rationale: Allows innovation without destabilizing existing business.

6. Trade-off: Higher short-term investment for long-term flexibility.

7. Risk: Cultural resistance from legacy IT teams.

8. Roadmap: Phase 1: Stand up cloud platform; Phase 2: EV customer portal; Phase 3: Integration with manufacturing; Phase 4: Full transition.

9. Validation: Time-to-market for new features, customer satisfaction scores, cost per vehicle.

Case 2: Financial Services API Strategy

Architect Level Medium

📌 Scenario

A regional bank wants to become an "open bank" with APIs for third-party developers. They have:

  • Core banking system from the 1990s
  • Strong regulatory compliance culture
  • Limited internal API expertise
  • Competitors moving faster
  • High security requirements

Your Task

Use the 9-step defense pattern for an API strategy recommendation:

  1. Context → Objective → Constraints → Recommendation → Rationale → Trade-off → Risk → Roadmap → Validation
📖 View Model Answer

1. Context: Regional bank with legacy core, need to enable open banking.

2. Objective: Launch secure developer APIs within 18 months.

3. Constraints: Regulatory compliance, security, limited internal skills.

4. Recommendation: Build API gateway with security-first design, start with read-only APIs.

5. Rationale: Reduces risk while building internal capability.

6. Trade-off: Slower initial feature set for better security.

7. Risk: Security breach or regulatory compliance failure.

8. Roadmap: Phase 1: Internal APIs; Phase 2: Partner APIs; Phase 3: Public APIs.

9. Validation: Number of developers using APIs, API uptime, security audit results.

Case 3: Healthcare Provider Consolidation

Architect Level Complex

📌 Scenario

A healthcare network has acquired 5 hospitals with different IT systems. They need to:

  • Share patient records securely
  • Unify billing and claims processing
  • Comply with HIPAA and patient privacy
  • Reduce IT operational costs
  • Maintain hospital autonomy where needed

Your Task

Use the 9-step defense pattern for a consolidation architecture:

  1. Context → Objective → Constraints → Recommendation → Rationale → Trade-off → Risk → Roadmap → Validation
📖 View Model Answer

1. Context: 5 hospitals, diverse IT systems, need consolidation.

2. Objective: Unified patient records and billing within 3 years.

3. Constraints: HIPAA compliance, physician buy-in, budget.

4. Recommendation: FHIR-based integration hub with central data warehouse.

5. Rationale: Preserves hospital autonomy while enabling unification.

6. Trade-off: Integration complexity vs. system replacement cost.

7. Risk: Data quality and standardization issues.

8. Roadmap: Phase 1: Patient index; Phase 2: Clinical data; Phase 3: Billing; Phase 4: Full analytics.

9. Validation: Patient data accuracy, billing error reduction, cost savings.
